How does the gateway decide between the worker pool and the cache when a request misses the edge?
Người thầy · Giảng giải
The gateway checks Redis before it ever touches the pool. A hit returns the cached payload and skips the worker. A miss enqueues the job, and the worker writes the result back with a short TTL so the next caller does not stampede the origin. The video walks that branch at 4:12, then shows the retry budget: three attempts, jittered, and only for the idempotent GET. Names in the auto captions say “cash” here; the description calls it Redis.
What should I watch before the retry section?
Người thầy
Start with the idempotency key, then the queue. The retry section assumes you already know that a failed worker does not roll back the cache write. If the key is reused, the gateway treats the second call as the same job and will not enqueue again.
